Both SELECT operations returned 9000. Eleven-stage

## Native ECDH

ALG_EC_SVDP_DH_PLAIN (0x03) succeeded on the tested
research curve.

Reported totals:

- native-ec: 110/180 APDUs verified
- pace-gm: 130/300 APDUs verified

These counts describe successful tested APDUs within
the full benchmark operation sets. They must not be
interpreted as all remaining APDUs failing ECDH.

All reported successful native ECDH responses matched
host reference arithmetic byte-for-byte.

For wide public scalars between 2 and 251 bits,
median transmit latency remained approximately
85.6–85.9 ms.

The stable timing across scalar bit lengths supports
the native-coprocessor hypothesis, but does not
establish side-channel resistance.

## RSA coprocessor

- Modulus size: 1024 bits
- Exponent: 3
- Operation: modular exponentiation, NOPAD
- Median transmit latency: 241.751 ms
- Verified responses: 10/10

Results matched host-computed reference values.

The measurement includes PC/SC transmit overhead
and response transfer. It is not a pure cryptographic
engine execution time.

## PACE-GM and XY provider compatibility

On the published applet:

- ALG_EC_PACE_GM (0x05): SW 6F02
- ALG_EC_SVDP_DH_PLAIN_XY (0x06): SW 6F02

The developer localized the PACE-GM failure to
uninitialized-key/provider configuration.

Adding `key.setK((short)1)` at initialization step 7
enabled the tested PACE-GM operation on JCOP4.

The corrected experimental variant used package
AID F0424E3235344D00.

The published applet and CAP were not modified.

`K=1` is not the research curve's mathematical
cofactor, which is 8. The workaround is not a
general subgroup-safety or arbitrary-point guarantee.

## PACE-GM latency

| Measurement | JCOP3 published | JCOP4 K=1 |
| --- | ---: | ---: |
| Median transmit latency | 222.923 ms | 150.046 ms |
| Published vectors | 10/10 | 50/50 |
| Minimum latency | Not reported | 149.144 ms |
| Maximum latency | Not reported | 168.936 ms |

JCOP4 median latency is approximately 32.7% lower,
equivalent to a 1.49x speedup for the measured operation.

The comparison uses the same reported per-APDU
transmit convention, not CLI-inclusive timing.

## Security boundary

All described scalar inputs were fixed public
test values. No wallet signing, PIN operations,
private-key export, or wallet provisioning was
part of the reported benchmarks.

Native arithmetic compatibility is not a complete
RAILGUN EdDSA-Poseidon signing implementation.
